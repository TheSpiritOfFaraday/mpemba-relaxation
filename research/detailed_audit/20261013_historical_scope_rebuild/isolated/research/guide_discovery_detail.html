From trying examples to proving a whole claim: a slow introduction

1. Start with one adjustable number

Suppose you can choose a number x between 0 and 1. For each choice, a calculation gives a score f(x). You want to know whether the score stays positive. Trying x = 0 and x = 1 gives two answers. It does not yet tell you what happens between them.

Take f(x) = (x−½)²−¹⁄₁₀. At either endpoint, f = ¼−¹⁄₁₀ = ³⁄₂₀ = 0.15. At the middle, f(½) = −0.1. Both endpoint tests pass, while an interior test fails. The issue is not that the computer calculated incorrectly. The tested points did not cover the claim.

2. Add a second adjustable number

Two parameters make a rectangle of possible choices. Checking its four corners still says nothing about an arbitrary nonlinear function inside it. With eight parameters there are 2⁸ = 256 corners, but infinitely many interior points. A corner reduction requires an additional mathematical argument, such as suitable monotonicity in every parameter. Counting corners is not that argument.

Checking one parameter at a time is weaker still. For f(x,y) = 0.1−xy with x and y between −1 and 1, each coordinate axis has f = 0.1. Changing both parameters to 1 gives f = −0.9. Interactions can hide entirely from single-parameter tests.

3. Translate a cooling target into a numerical score

Fix a target distance δ from equilibrium. Let tc be the time the cold preparation first reaches that target. A 5% time saving means the hot preparation reaches it by 0.95tc. For the decreasing KL distance in this study, it is enough to check Dh(0.95tc) ≤ δ.

Divide by the positive number δ and subtract 1. The resulting score is Dh(0.95tc)/δ−1. A score at most zero passes the target. If there are several tested thresholds, take the largest score: every tested threshold passes exactly when that maximum is at most zero. This still covers only the thresholds and parameters actually tested.

4. Understand what an optimizer does

An optimizer chooses new parameter values using previous scores. A random seed makes its random choices reproducible under suitable software conditions. It does not turn a finite search into a proof. Different library versions or floating-point arithmetic can change which point is tried next.

Two questions must remain separate: “What was the best point found?” and “Did the algorithm satisfy its stopping rule?” A run can stop at its iteration limit, report success=false, and still return a useful point. All three saved adversarial searches here have that status. Their candidate savings can be checked directly; their status does not establish that a better or worse point is impossible.

5. Learn from the rejected candidates

The first physical search optimized the nominal system. The second screened individual parameter changes. The refinement then evaluated combinations at all 256 corners and used adverse corners to guide further searches. Its first accepted improvement still had a positive worst-corner score, about 0.03630: it was better than its predecessor, but still failed a target. The next stages made that tested worst score negative, about −0.00365.

“Accepted by a refinement algorithm” therefore means “better under that algorithm's comparison,” not “proved to satisfy the research goal.” The eventual continuous guarantee comes from the separate interval certificates and their analytic reductions.

6. Check the evidence without inheriting the search's calculation

The new audit recomputed all 153 saved improving search points, both final search scores, the refinement scores and decisions, and the three adversarial candidate savings. It used direct matrix exponentials in physical time rather than the search's spectral propagation. All 166 numerical comparisons passed; the largest absolute discrepancy was below 8×10⁻¹³.

That agreement checks the recorded point values. It does not, by itself, authenticate historical elapsed times, every unsaved trial, or a global optimum. A fresh replay and a mathematical certificate answer different questions, and both should retain their stated scope.

Inspect the independent calculation and its source-bound receipt. The exact rational examples above require only multiplication and subtraction; the advanced physical certificate uses interval bounds to cover unsampled points.

Why a promising candidate can fail: from one inequality to exact rejection

1. A counterexample must satisfy every assumption

Suppose a claim says, “Every number x satisfying x ≤ 0 also has property P.” A proposed counterexample needs both x ≤ 0 and failure of P. The number x = 0.000000001 does not qualify, even if it is very close to zero. Replacing the condition by x ≤ 0.000001 changes the problem.

A numerical solver may allow a small residual when it tests an inequality. That tolerance is useful during exploration, but the exact mathematical claim keeps its original boundary. In one retained inverse search, a numerical candidate was promising enough to save. Exact rational reconstruction then found seven positive triplet tests, including F234 ≈ 1.30×10⁻⁷. It was correctly rejected.

2. A prescribed mode can be correct while the rates are wrong

The first rational backward design had the desired eigenvector and eigenvalue. That means its linear eigen-equation was satisfied. Nevertheless, its 1–2–4 triplet had positive F and G, so it violated the required premise. Solving the eigen-equation was only one part of the job. A revised choice of adjustable rates satisfied the premise and matches the independently certified rational companion.

3. A ratio can magnify a nearly zero error

Consider a diagnostic ratio a/b. If both a and b should be almost zero, tiny rounding errors can dominate the ratio. For example, a computed numerator −10⁻¹⁶ divided by a computed denominator 10⁻¹⁶ gives −1. A large-looking ratio need not represent a large physical or mathematical violation.

A saved six-state search point produced a negative arithmetic diagnostic. Its high-precision recheck did not confirm a violation. We can now reject it exactly: subtracting the minimum reset leaves two connected groups, states {1,2,3,4} and {5,6}. The relevant slow mode is constant within each group. Calling its first-group value a, the tested expression is w₁+w₂−2w₃ = a+a−2a = 0.

The advanced justification uses reversibility: the internal dynamics has exactly two zero modes, one per connected group, while all its other modes decay. Adding the reset leaves one equilibrium mode and shifts the other component-constant mode to eigenvalue −1. Every remaining mode is faster. Thus the zero arithmetic margin belongs to the actual simple slow mode. This settles this stored candidate, not the general higher-dimensional question.

4. Count attempts and retained checks separately

The broad heating search recorded about 6.74 billion attempted derivative evaluations. Positivity and signal-size filters excluded some points from the score comparison; spectral and bath-weight filters also restricted which systems were sampled. The later optimizer's roughly 66.4 million objective calls included penalty returns for excluded inputs. Those totals are not counts of certified mathematical cases.

The surviving best scores remained positive, including under separate high-precision calculations. The report now states the filters explicitly. A finite search with no accepted negative score still leaves the general mathematical question open.

5. Keep the successful and unsuccessful records together

The original cone, positive-rate, and signed-rate searches reproduced their saved candidate or final records exactly. The rejected rational design, the seven-inequality failure, and the borderline six-state case remain available alongside the successful certificates. This makes the reasoning inspectable: a candidate becomes evidence only after the checks appropriate to its claim.

Reproduce a result without confusing the command, its output, and its proof

1. A command is a recipe with ingredients

A program name alone does not identify a calculation. Its arguments choose inputs and settings; its working directory determines where relative paths begin. For example, --samples 3000 requests 3,000 interior samples in addition to the 256 corners. Omitting it invokes a different default. A reproducibility record therefore keeps the full command, the inputs, the source version, and the result.

2. A fingerprint identifies a file, not a theorem

A SHA-256 hash is a compact fingerprint of a file's bytes. If an input changes, its fingerprint almost certainly changes. Matching fingerprints help establish that two runs used the same data or code. They do not establish that the code implements the right mathematics. That requires inspecting formulas, assumptions, boundary cases, and error handling.

3. Read the success conditions carefully

A process exit code of zero conventionally means that the program finished successfully. It means only what that program actually checked. The replay wrapper also writes complete and all_passed: the first says the sequence ended, while the second says every child check passed. Read both. For a continuous interval proof, also check that no cells remain pending and that no enclosure errors occurred.

A useful negative control deliberately supplies a false claim or invalid input. The test passes when the verifier rejects it. This helps check that “success” is not an unconditional printed message. It supplements the proof of the verification method; it does not replace that proof.

4. Separate document rebuilding from checking mathematics

The isolated document rebuild recreated all three LaTeX sources byte for byte. The rebuilt PDFs also had identical page text and drawing content: 126 pages for the report, 81 for the appendices, and 10 for the focused paper. This checks that the advertised recipe preserves the reviewed documents. It does not independently re-prove their theorems.

PDF files can contain creation timestamps, so two files can display exactly the same pages while their whole-file hashes differ. Compare the relevant content before deciding what a difference means. Preserve the original artifacts while investigating.

5. Understand the formal check's boundary

The Lean command builds the pinned project and checks axiom reports for 43 named theorems. The fresh run passed with only the permitted standard logical axioms. Its mathematical scope is the specific formal statements: it does not automatically cover every numerical figure, physical-model claim, or literature attribution in the report. The guide's earlier lessons explain those separate evidence requirements.
